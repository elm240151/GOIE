# UI 设计规范

## 技术约定

- React 18 + Zustand 单 store（client/src/store.ts）：屏幕路由 + 房间状态 + 快照 + 选牌 + Toast，**全部由服务端广播驱动**，客户端零规则判定
- 所有中文文案集中在 `client/src/strings.ts`（`STR` 对象），**界面零硬编码**；改文案只动这一个文件
- 样式单文件 `client/src/styles.css`：mobile-first，CSS 变量（`--felt` 深蓝桌布 + `--gold` 金色点缀、牌面白、牌型色；用户不喜欢绿色，2026-09-27 已从绿色系换为深蓝系）；手机竖屏优先，桌面居中放宽
- 组件：Card / Hand / ComboBadge / PlayerSeat / RoleCard / SkillAskModal / Toast；屏幕：Lobby / Room / GameTable / Scoreboard

## 屏幕

| 屏幕 | 内容 |
|---|---|
| Lobby | 玩家名（localStorage 记忆）、创建房间、输 6 位房号加入、战绩入口、连接状态 |
| Room | 大号房间号 + 复制、座位列表（房主/你/掉线徽章、已选角色、已准备）、角色选择网格（名字/技能名/技能说明，被选中的显示是谁；**按席位序 首席→末席**，RoleDef.seatOrder）、准备/取消准备（未选角色时显示「先选角色」）、房主「开始」（≥2 人且全 ready） |
| GameTable | 上家/下家/对面座位（淘汰座位变灰 + 已淘汰标 + **迷你牌背堆**直观显示手牌张数 + **红楼梦徽章**（橐驼诅咒目标：金色闪烁「红楼梦」标）+ **点座位弹角色技能**（「别人的技能也能看到」，RoleViewModal 复用 role-skill-block））、中央出牌区（ComboBadge + **答疑改点展示**（修勾改判定点后 ComboBadge 金色主显新点数 label + 旁注小标「改判：原X」，悬浮说明按新点数判定）+ **中央牌堆卡背叠**（5 张封顶 + 张数，顶部牌背随摸牌脉冲；弃牌堆数字在顶栏）+ **明置边牌**（再问补打等：迷你牌与当前一手牌并列展示，随桌面一起清除）+ **本回合暂存区**（线下打牌感：本回合除当前一手外的所有牌以「谁出的 + 小徽章」堆叠暂存，判定牌小卡单列「判定」标，回合结束统一清空）+ **瞬时翻牌**（非判定 purpose：观股/茄汤等逐张亮出动画后自动消失））、手牌一横排点选 + 实时牌型预览（**新摸入的牌从上方飞入**；**单王预览**：橐驼的王按角色 soloJoker 解锁，选中单王即显示「王」牌型）、出牌/过、**出牌记录条双形态**（同一 RoundHistory 组件两实例：移动端牌桌顶部横条、≥1000px 桌面端右侧竖排条，最新一手金框高亮自动滚入，回合结束统一清空）、**我的技能条**（角色边上点开可读说明，可发动时金色高亮）、主动技按钮行（skillActions）、**整理手牌**（开关 + 点数/花色/颜色快捷排序 + 点两张牌交换，顺序按玩家持久化 localStorage）、技能询问弹窗（SkillAskModal）、手牌 x/20、30s 倒计时、技能 Toast（含**地坛取而代之**：「【地坛】{name} 取而代之，摸 {n} 张继续出」）、终局弹窗（赢家/流局 + 记分表 + 再来一局投票，**全票通过后回到房间界面**重新选角色/准备，不自动开局）、断线重连遮罩 |
| Scoreboard | 战绩列表（时间/房间/赢家/玩家/分数） |

## 组件规格

- **Card**：白底圆角，颜色用共享 `cardColor`（♥♦大王红、♠♣小王黑）；王：双角标「王」+ 中央星徽 ✦ 与大小徽章（大王红字、小王黑字，金框 + 内虚线框）；点选态上浮高亮；`asRank` 预览模式（牌型解析后的百搭显示为其所当的点数，徽章在牌底居中）
- **Hand**：一横排对齐（全部正立，不旋转）；牌多时槽位 flex-shrink 自动加大叠压保证一排装得下（min-width = 牌宽 30%，晚出的牌压前面）；选中上浮；**新摸入的牌飞入动画**（快照手牌 diff 识别 enteredIds，内层 wrapper 动画不与横排叠压冲突；多张同时摸入按序错开；首局发牌不播放；跨局清空标记——每局牌 id 重新编号）
- **ComboBadge**：牌型名 + 颜色（单张/对子/顺子/连对/炸弹各一色）+ 解析后迷你牌行（点数下方带**花色符号**红黑着色，百搭标注「鬼」），如「对7 7♠·鬼」「顺子 3♣-4♦-5♥-6♠」
- **PlayerSeat**：头像占位（名字首字）、名字、手牌数、角色徽章、掉线标、淘汰态（灰化 + ✕ 头像 + 已淘汰标）、回合高亮圈 + 倒计时、过牌气泡（2.5s 自动消失）、**牌背堆**（最多叠 8 张迷你牌背，其余看 ×N，淘汰后隐藏）、**红楼梦徽章**（`snap.cursedPlayerIds` 命中：金色闪烁「红楼梦」小标，下回合不得出牌）、**点击座位查看该玩家角色技能**（onView → RoleViewModal）；各座位出的牌统一展示在**中央暂存区 + 出牌记录条**（roundPlayLog），不在座位上重复展示
- **公开判定牌展示区（GameTable 中央）**：监听 cards:revealed 事件累积成流，逐张翻牌入场动画（每张延迟 0.4s，封顶 12 张显示 + 共 N 张标注），下一次回合/出牌/轮末/淘汰事件后按张数延迟清除（约 1.4s + 0.45s×张，留出动画时间）；**不同用途（purpose）的翻牌流不混合**——新流开始时清空旧流重新累积（如茄汤亮牌与黑脸判定分开显示，避免"看起来少摸牌"）；快照 revealed 池在询问挂起期间并入（观股选牌、重连都能看到）
- **我的技能条（my-skills）**：角色 skills 逐个渲染成 chip「【技能名】」，点开浮出说明（锁定技带徽标）；与 skillActions 同条件判定"可发动"时金色脉冲高亮
- **整理手牌（organize-bar）**：🃏整理开关 → 显示点数序/花色序/颜色序快捷排序 + 提示；开整理后点一张选中、再点另一张交换位置；顺序存 localStorage（`gdys-handorder-{playerId}`），新摸的牌按默认排序追加末尾
- **RoleCard**：角色名 + 逐技能【技能名】（锁定技徽标）+ 技能说明（来自 RoleDef 的 skills，**新角色自动展示零改动**）
- **SkillAskModal**：按 ask.kind 通用渲染——confirm（确定/放弃）、suit（花色按钮）/choice（通用选项按钮，如骚骚换 1/2 张）、pickCards（选牌网格 + 数量校验 + 提交；`hidden` 时渲染**牌背盲抽**；带**放弃按钮**——再问补打「打不出」、观股大跌放弃等）、pickTarget（目标按钮）、cutIn（自己手牌选接牌组合）、selfFollow（修勾狂吠：与 cutIn 同渲染——自己手牌选牌压自己打出的牌，可连压，放弃轮到下家）；带 15s 倒计时（≤5s 红色脉冲）；每次新 askId 重置选择
- **Toast**：顶部滑入，技能播报 `【技能名】text`（来自服务端 `announce`，按 skillId 在 skills 里查技能名）、亮牌/淘汰提示、游戏错误、轮末摸牌提示

## 设计原则

1. **预览不阻断（★ 重要）**：客户端用 shared 的 `parseCombo/canBeat` 做即时预览，但"压不过/不是合法牌型"只显示黄色提示（`（技能可能豁免）`），**不禁用出牌按钮**——技能优先原则下客户端永远不能替服务端做最终裁决，非法出牌以服务端 `game:error` 为准
2. 非法牌型（王单独出、纯王组合）禁用出牌（这是结构性非法，技能也不豁免）
3. 过按钮：新一轮起牌者禁用（规则：起牌必须出牌）；技能询问弹窗打开时动作被弹窗遮罩挡住，且服务端对挂起期间的动作回「等待技能响应」；**防误触两次确认**：已选牌时第一次点过只清空选牌 + Toast 提示、按钮变琥珀「确认过牌？」，3s 内再点才真正过牌（换回合/桌面变化/新询问/重新选牌/开整理/超时均立即复位）；未选牌直接过
4. 主动技按钮来自 `skillActions`（`myTurn` = 轮到自己；`following` = 接牌时），通用渲染不硬编码角色
5. 所有规则解释文案用中文，与 strings.ts 一致
6. 状态展示优先用服务端字段（handCount、eliminated、pendingAsk 等），不自己推断

## 用户 UI 调整请求的处理流程

1. 记录到当天 dev-log 的待办
2. 明确需求（要什么效果、在哪个屏幕）→ 改 strings.ts + 对应组件/样式
3. 手机宽度 + 桌面宽度各验证一次
4. 汇报改动 + 让用户试玩确认
