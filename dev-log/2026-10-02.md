### 生产服务器崩溃修复（观股超时弃权 → 翻牌池泄漏 → 进程死亡）

**现象**：生产服务运行数小时后崩溃退出，日志栈指向 `GameEngine.resolveAsk` 抛「翻牌池未清空（角色技能泄漏）」——技能询问超时定时器回调无任何异常保护，未捕获异常杀死整个 Node 进程。

**根因**：观股大跌选牌阶段（池中已有 5 张判定牌）玩家超时/弃权时，弃权分支直接 `return` 未清空翻牌池；引擎守恒断言在 `resolveAsk` 收尾抛异常。此前测试只覆盖「确认阶段超时弃权」（池为空），恰好漏掉此路径。

**修复（两层）**：

1. **根因**（shared/src/roles/zecheng.ts）：弃权分支若 `st.revealedIds` 非空 → `discardRevealed()` + 清态 + 播报「弃权，判定牌弃置」，按正常摸牌处理
2. **安全网**（server/src/room.ts）：新增 `abortGame()`（引擎异常 → 本局安全终止：phase=finished、winnerId=null、不记分、广播提示，全员可再来一局）；play/pass/useSkill 与两个定时器回调（询问超时、掉线自动过）全部加 try/catch——**任何角色 bug 都不再能杀死服务器进程**（requireEngine 的阶段校验仍在 try 外，大厅出牌照常报「游戏不在进行中」）

**回归测试**：zecheng 新增「大跌选牌阶段弃权：判定牌弃置、正常摸牌、不触发守恒断言」；room 新增「引擎异常安全网：回答询问时抛异常 → 本局安全终止、不向上抛出、可再来一局」（Proxy 模拟角色 bug）。

**验收**：npm test 全绿（shared 131 + server 15）+ 三包 tsc + client build + 烟测全绿（烟测还当场抓出安全网第一版误吞「大厅出牌被拒」的边界，已收紧 try 范围修复）。生产服务已带修复重新上线（3000）。
