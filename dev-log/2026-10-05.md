### R.F 吐饼（rf）—— 吃饼（第十七位角色）

按用户要求「先弄清楚概念」：实现前经**四轮 AskUserQuestion 逐条确认**技能细节，全部定稿后才动手。用户最终批准原话：「基本正确 唯一要注意的是措辞问题 rf的吃饼算特殊响应但不算出牌 后续角色可能会对这个点有限制 你可以实现了 再有问题会告诉你」。

定稿口径：

- **触发**：任何人每次出牌后（物理出牌者 ≠ R.F，含插队/狂吠每手/翻面接；归属改写不改物理出牌者）**最先询问 R.F**——先于狂吠/插队；每手限问一次、无上限
- **恰好接上** = 同型同长且 rank 恰差一级（正序 +1、倒序 −1）：A↔2 自然衔接、2 压非 A 不算；炸弹同张数差一级才算；单王/对王/首席 Q 压一切类不算；王按所当点数；顺子/连对按起点 rank 差一级
- **吃饼三阶段**：①自选一组恰好接上的牌公开亮出（留在手中，`cards:revealed` purpose 吐饼亮牌）→ ② rawDraw N（N = 桌面牌张数；手牌上限淘汰照常 = 输）→ ③ 自选 N 张倒置成饼（`pancake:flipped` 只公开张数、永久牌背、任何人不可看不可用）
- **获胜**：饼数 ≥ 手牌数 → 立即获胜；**他人打完手牌的获胜判定先于吃饼询问**（afterPlayCommitted 获胜判定在 offerPancake 前）
- **牌权**：桌面归属不变、后续玩家照常接；轮末起牌权归吃饼者（provisionalLeadId）
- **过牌**：吃饼不消耗响应，但轮到他时不能再过——无牌权时只能打 2（倒序 3）/炸弹，无则自动过
- **首席 Q 特判**：桌面单 Q + roundLastPlayerId 是首席 + prevTableCombo 非单 J → 不询问（压自然 J 出的 K 属恰好接上、照常可吃饼）

实现落点：

- **engine.ts**：`pancake` 标志 + PendingAsk kind 'pancake'（resolvePancake 两阶段 pickCards：亮牌 → 倒饼；decline/超时干净作废、倒置阶段超时自动倒前 N 张）+ 吃饼后响应限制（pancakeNoPass/只能打 2 或炸弹，自动过）+ provisionalLeadId + 快照 pancakeCount
- **combos.ts**：恰好接上判定（canExactFollow：同型同长 rank ±1，倒序 −1、王按所当点数、顺子/连对按起点、首席 Q 特判在询问层）
- **server**：pancake 询问收发/超时走通用 ask 通道，pancake:flipped 广播
- **client**：无牌权金色提示（恰好接上的牌请走吃饼询问）、吃过饼「过」按钮禁用（无 2/炸弹自动过）、座位与手牌旁 🍪 饼数徽章（标题注明牌背不可看不可用）
- **simulate.ts**（草稿脚本，不提交）：15× 种子化全流程模拟补上 R.F 两阶段询问策略；守恒公式补翻牌池 + tableSide + 饼

### 修复：回味被修勾狂吠误触发（用户实机 bug，2026-10-05）

用户原话：「修勾的狂吠应该是自己压的自己 为什么在接了楠王的牌以后 每次狂吠都会触发回味呢」。

**根因**：引擎 `orderedHooks('afterPlay')` 对**全场每个角色的每次出牌**都会跑一遍钩子（不分出牌者是谁），而楠王回味钩子里只有「被压者存在且不是楠王」的守卫、**没有「本手出牌者必须是楠王」的守卫**——修勾狂吠压自己的牌时 prevTableOwnerId = 修勾本人 ≠ 楠王 → 误判成「压牌」给修勾摸牌；同理任何玩家压任何非楠王的玩家都会误触发。

**修复**（king-nan.ts 回味钩子顶部加守卫）：`if (ctx.game.roundLastPlayerId() !== ctx.self.id) return;`——afterPlay 时 roundLastPlayerId = 本手出牌者（含狂吠/翻面接/插队等全部提交路径；亢奋归属改写后 = 惰戈，与「这手牌触发的后续技能判定一律对新 owner 生效」一致：楠王的手被归属惰戈后不算楠王压牌）。

**回归测试 ×2**（king-nan.test.ts）：①修勾狂吠场景复刻（楠王起 ♠5 → 修勾 ♠6 压 → 旺旺询问弃权 → 修勾 ♠7 狂吠自压：无 hui-wei 事件、修勾手牌 8−2、牌守恒）②通用场景（p2 起 ♠5 → 楠王过 → p1 ♠6 压：无回味、p2 手牌 8−1、旺旺不询问）。修复前两用例均红、修复后全绿。
